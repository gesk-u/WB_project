# Sanahaku — Sprint 2 Documentation

This directory contains the Sprint 2 implementation artifacts, Scrum process records, and team reflections for Sanahaku, a web platform built to help language learners hear natural, conversational Finnish pronunciation in timestamped YouTube videos.

## Sprint 2 Overview

**Sprint Goal:** Implement the frontend and backend of Sanahaku as independent, functioning codebases — frontend with mock data and full navigation, backend with a working MVC structure, database, and tested API endpoints — in line with the Sprint 1 prototype, without yet connecting the two layers.

**Team Members:**
- Anastasiia: Backend 
- Georgs: Backend 
- Maria: Frontend 
- Veranika: Scrum Master & Frontend

**Sprint Status:** Finished.

---

## 1. Alignment with Sprint 1 Prototype

Sprint 2 implementation was built directly on top of the prototype defined in Sprint 1.

- All pages and flows from the Sprint 1 prototype were implemented **except the third page**, which was reserved for the AI-based feature.( AI functionality was planned as a 3 Sprint feature )
- The frontend and backend were built as two separate, independent codebases, with no integration between them yet. This matches the Sprint 2 requirements, which explicitly call for a functional frontend representation using mock/static data, and a backend built around mock/array data and its own database — not a connected full-stack application.
- Navigation, page structure, and UI sections in the frontend follow the layouts and user flow agreed upon in the Sprint 1 Figma prototype.

**Summary:** Sprint 1 prototype alignment was maintained across all core pages and flows, with the AI feature page deferred and frontend/backend deliberately kept unconnected, as intended for this sprint.

## 3. Adherence to Scrum Process

- **Sprint Planning:** Sprint 2 backlog items were derived from the Sprint 1 backlog and prototype, split into frontend and backend workstreams.
- **Roles:** Veranika continued as Scrum Master + contributed to frontend searching page(first) development, Maria focused on frontend results page(second) development + styling both pages, Anastasiia focused on all the main backend functionality -  MVC structure, data structures, cloud database integration, controllers, routes, CRUD endpoints, and finally Georgs focused on the backend authentication part. 
- **Daily/Regular Check-ins:** The team held regular stand-ups to track progress on frontend and backend tasks separately, given the two workstreams were developed independently.
- **Definition of Done:** A task was considered done when frontend components rendered correctly with mock data and passed visual/functional review, or when backend endpoints were implemented, tested via Postman/Bruno, and returned correct responses.
- **Sprint Review & Reflection:** The team reviewed completed work against the Sprint 1 prototype and the official Sprint 2 requirements, confirming that all mandatory frontend and backend elements were delivered.
